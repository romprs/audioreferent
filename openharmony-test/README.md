# Тест распознавания русской речи на OpenHarmony 6.1

Отдельный мини-проект, никак не связанный с Python-кодом для РЭД ОС в
корне репозитория. Цель — проверить на реальном устройстве, справляется ли
системный речевой движок (Core Speech Kit) с распознаванием русской речи,
прежде чем вкладываться в полноценный порт ассистента под OpenHarmony.

## Важная оговорка

Код использует API `@kit.CoreSpeechKit` (`speechRecognizer`), задокументированный
для HarmonyOS NEXT (частая путаница: телефоны на HarmonyOS собраны поверх
открытого проекта OpenHarmony, но проприетарные «кит»-API вроде Core Speech
Kit принадлежат HMS Core от Huawei, а не самому open-source OpenHarmony).
Если ваше устройство — HarmonyOS-смартфон, это должно быть доступно. Если
это community-сборка «чистого» OpenHarmony без HMS Core — импорт
`@kit.CoreSpeechKit` не найдётся вообще, и это будет ценным результатом теста:
значит нужен другой путь (например, захват аудио через `@ohos.multimedia.audio`
и распознавание где-то ещё). Также нет гарантии, что движок поддерживает
`ru-RU` — это тоже часть того, что должен показать тест. **Просто сообщите
мне, на каком шаге и с какой ошибкой (если) всё остановится — донастрою.**

## Шаг 1. Установить DevEco Studio

1. Скачать DevEco Studio с сайта разработчика (Huawei Developer, раздел
   DevEco Studio) под вашу ОС (Windows/macOS/Linux).
2. Установить, при первом запуске дать ему докачать OpenHarmony/HarmonyOS
   SDK через встроенный SDK Manager (Settings → SDK Manager) — выбрать SDK
   API-уровень, соответствующий OpenHarmony 6.1 на вашем телефоне (если
   отдельного пункта «6.1» нет, взять ближайший доступный API-уровень —
   уточним, если возникнут ошибки совместимости).

## Шаг 2. Создать проект

1. File → New → Create Project.
2. Выбрать шаблон **Empty Ability** (ArkTS, Stage model).
3. Application name: `AudioreferentTest` (или любое), Bundle name — любой,
   например `com.example.audioreferenttest`.
4. Compile SDK — выбрать установленный в шаге 1.
5. Finish — DevEco Studio сгенерирует полный проект со всеми служебными
   файлами (`AppScope`, `hvigor`, конфиги сборки, иконки) — их трогать не
   нужно, они не входят в этот репозиторий специально, чтобы не гадать
   с версиями инструментов.

## Шаг 3. Добавить разрешение на микрофон

Открыть `entry/src/main/module.json5` в созданном проекте и добавить в
массив `"requestPermissions"` (создать массив, если его нет) на уровне
`"module"`:

```json5
"requestPermissions": [
  {
    "name": "ohos.permission.MICROPHONE",
    "reason": "$string:microphone_permission_reason",
    "usedScene": {
      "abilities": ["EntryAbility"],
      "when": "inuse"
    }
  }
]
```

И добавить строку `microphone_permission_reason` в
`entry/src/main/resources/base/element/string.json`:

```json
{ "name": "microphone_permission_reason", "value": "Нужен доступ к микрофону для распознавания голосовых команд" }
```

## Шаг 4. Подставить код страницы

Открыть сгенерированный `entry/src/main/ets/pages/Index.ets` и полностью
заменить его содержимым файла [`src/pages/Index.ets`](src/pages/Index.ets)
из этой папки.

## Шаг 5. Подключить телефон и запустить

1. На телефоне включить режим разработчика и отладку по USB (обычно:
   Настройки → О телефоне → несколько раз тапнуть по номеру сборки → в
   появившемся разделе «Для разработчиков» включить отладку по USB).
2. Подключить телефон кабелем к компьютеру, разрешить отладку в диалоге на
   экране телефона.
3. В DevEco Studio в выпадающем списке устройств сверху должно появиться
   ваше устройство (использует `hdc` — HarmonyOS аналог `adb`, идёт в
   комплекте с SDK). Если не появилось — Terminal → `hdc list targets`.
4. Нажать Run (зелёный треугольник). Приложение соберётся и установится на
   телефон.

## Что проверяем

1. Приложение открывается, просит разрешение на микрофон — подтвердить.
2. Нажать «Старт», сказать в микрофон: «Вика, открой браузер».
3. Смотреть на экран:
   - Текст ниже статуса — то, что распознал движок.
   - Строка статуса зеленеет и показывает «Ключевое слово обнаружено» при
     срабатывании на «вика» (с учётом простых опечаток распознавания —
     проверка на подстроку, без чувствительности к падежам, если движок
     произвольно изменит слово — сообщите, добавим нечёткое сравнение как
     в основном проекте).

## Результат, который мне нужен

После первого запуска пришлите:
- Открылось ли приложение и не упал ли импорт `@kit.CoreSpeechKit` при
  сборке (это сразу скажет, доступен ли Core Speech Kit на вашей прошивке).
- Что показывает поле распознанного текста при разных фразах на русском.
- Текст любой ошибки из `onError`, если она появится (особенно про язык —
  вероятная проблема с `ru-RU`).
